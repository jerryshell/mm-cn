# 贡献指南

欢迎改进翻译。这个项目的翻译流程是**可复现、可审阅**的，所以改一条文案不需要
重跑整条流水线，也不需要显卡和游戏运行环境。

---

## 一、环境准备

```bash
pip install -r requirements.txt      # UnityPy / Pillow / numpy / scipy / fonttools

# 指向你的游戏目录（默认是 D:\SteamLibrary\...）
set MM_GAME=D:\SteamLibrary\steamapps\common\Motorsport Manager
```

只需要一次（每台机器跑一次即可）：

```bash
python tools/extract.py         # 从游戏里导出原始 CSV / 图集 / TTF
```

> `extract.py` 会优先使用安装脚本留下的 `resources.assets.orig`。
> 如果两个文件都是汉化版，它会直接报错退出 —— 拿汉化版当输入会毁掉工作数据。

## 二、改一条翻译

### 情况 A：术语翻错了（推荐这样做）

比如发现 `Podium` 被翻成了「讲台」而不是「领奖台」：

1. 打开 [`tools/glossary.py`](../tools/glossary.py)；
2. 如果是**某个短词条整体翻错**，加一条整句覆盖：

   ```python
   EXACT = {
       ...
       'Podium': '领奖台',
   }
   ```

   键必须是 CSV 里 `English` 列的**完整原文**（含标点和 `{变量}`）。

3. 如果是**某个错词普遍出现**，加一条短语修正：

   ```python
   FIXES = [
       ...
       ('讲台', '领奖台', False),      # (匹配, 替换, 是否正则)
   ]
   ```

4. 重新生成文本并校验：

   ```bash
   python tools/build_patch.py --text-only   # 约 30 秒，不用重算字体
   python tools/verify.py
   ```

### 情况 B：机器译文本身读不通

译文存在 `trans/zh_cache.jsonl` 里，格式是：

```json
{"k": "英文原文|原文长度哈希", "v": "中文译文"}
```

key 由 `translate.ckey()` 生成。要手工改一条：

```bash
python - <<'PY'
import sys; sys.path.insert(0, 'tools')
from translate import load_cache, save_cache, ckey

cache = load_cache()
en = '原文（从 CSV 的 English 列完整复制过来）'
print('原译文：', cache.get(ckey(en)))
cache[ckey(en)] = '手工改好的译文'
save_cache(cache)
PY
```

改完同样跑一遍 `build_patch.py --text-only` 和 `verify.py`。

> **注意**：如果直接在 `glossary.py` 里加了整句覆盖，就不必动这个缓存 ——
> 术语表的优先级高于缓存，而且改起来可读性好得多。能用术语表解决就别改缓存。

### 情况 C：发现某条没翻译

```bash
python tools/build_patch.py --text-only
```

如果输出里有「N 行保留英文」，会同时生成 `build/untranslated.txt` 列出这些条目。
按情况 A 加进术语表即可。

## 三、改完必须过的三关

```bash
python tools/build_patch.py --text-only   # 重新生成 dist/resources.assets
python tools/verify.py                    # 结构校验
python tools/preview.py                   # 出字体预览图（改字体时才需要看）
```

改了术语表之后，`verify.py` 里这几项会直接反映问题：

* **各语言列内容一致** —— 说明 10 个语言列都写到了；
* **`{n}` 占位符泄漏** —— 说明某个变量在还原时丢了，游戏里会显示成 `{12}`。

装机之后还可以跑终验收：

```bash
python tools/accept.py    # 42 项，读的是已安装到游戏里的文件
```

## 四、提交前请确认

- [ ] `python tools/verify.py` 全绿；
- [ ] `python tools/accept.py` 全绿（如果装了补丁）；
- [ ] 术语改动写进了 `tools/glossary.py`，而不是只改了 `trans/zh_cache.jsonl`；
- [ ] 如果新增了「有意保留拉丁字母」的词条，**同步加进 `KEEP_LATIN`**，
      否则 `accept.py` 会把这一条报成未翻译；
- [ ] 说明动机：是官方术语错了、读不通、还是缺翻译。附上英文原文和游戏里
      出现的位置（哪张表、大概哪个界面）会好审很多。

## 五、想动字体部分

字体代码在 `tools/sdf.py`（距离场生成）和 `tools/cjkfont.py`（图集打包与缩比）。
改之前建议先读 [`docs/技术说明.md`](技术说明.md) 里「字体」那一节，
里面写了 SDF 编码的推导过程和几个已经踩过的坑（`yOffset` 的方向、
浮点距离场必须用 `Image.F` 缩放、采样窗口必须正好是 `padding`）。

改动之后：

```bash
python tools/build_patch.py     # 完整重建，约 6 分钟
python tools/preview.py         # 出图肉眼确认
python tools/verify.py
```

`preview.py` 输出的图就是游戏里会画出来的样子，中文有没有被拉伸、
基线有没有歪，看图基本能判断。

## 六、不要提交的东西

`.gitignore` 已经挡好了，但说明一下原因：

| 目录 | 为什么不入库 |
| --- | --- |
| `extract/` | 游戏原始 CSV，版权属于开发商，且能本地重新生成 |
| `assets/` | 游戏原始字体图集 / TTF，同上 |
| `build/` | 中间产物 |
| `dist/` | 补丁成品（373 MiB）和 release 包，走 GitHub Releases 发布 |

**只有一个例外**：`trans/zh_cache.jsonl` 必须入库 —— 它就是本项目的翻译成果本体，
也是别人能审阅、能改进、能复现构建的前提。

`installer/*.bat` 是 GBK 编码的，`.gitattributes` 里声明了 `*.bat -text`。
不要用编辑器把它「转成 UTF-8 保存」，那会让脚本直接失效。
需要改脚本内容请改 `scripts/make_installer.py` 再重新生成。
